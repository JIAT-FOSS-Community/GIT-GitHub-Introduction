Part 1 — Context
What is Version Control?
The problem every developer has faced — and the solution.
Without Version Control
project_final.zip
project_final_v2.zip
project_ACTUAL_final.zip
project_USE_THIS_ONE.zip
project_FINAL_final_v3_real.zip

No way to know what changed, when, or why.

One accidental overwrite = everything lost.

Collaboration = emailing zip files back and forth.

With Git
feat: add login page
fix: resolve null pointer
docs: update README

Every change tracked with who, what, and when.

Made a mistake? Roll back instantly to any point.

Collaborate without overwriting each other's work.

Think of it as
A time machine for your code — go back to any point, see exactly what changed, and collaborate without stepping on each other's work.

Git vs
GitHub
Two different things — working together.
"Git is the engine.
GitHub is the road."
Git
Local version control tool
  • Runs entirely on your computer
  • Tracks file changes over time
  • Free, open source, works offline
  • Created by Linus Torvalds in 2005
  • Used via terminal / command line
Installed on: your machine
GitHub
Cloud hosting for Git repos
  • Website that stores Git repos online
  • Enables global team collaboration
  • Pull Requests, Issues, Actions
  • Home of 100M+ open source projects
  • Where Hacktoberfest happens
Hosted at: github.com

Part 2 — Setup
First-Time
Git Config
Tell Git who you are — once, globally.

Every commit is stamped with your name and email. This is how the open-source community knows who contributed what.

Use the same email you registered on GitHub — this links commits to your profile!
Git Bash / Terminal
# Set your name
$ git config --global user.name "Your Full Name"
# Set your email (must match GitHub)
$ git config --global user.email "you@example.com"
# Set default branch name
$ git config --global init.defaultBranch main
# Verify
$ git config --list
user.name=Your Full Name
user.email=you@example.com
Saved in ~/.gitconfig — do this once per machine.

Method 2: SSH Key Authentication
Generate key pair → keep private key secret → add public key to GitHub.
Focus Method
Step 1 — Generate & Config
# Generate key (press Enter 2x when prompted)
$ ssh-keygen -t ed25519 -C "you@email.com" -f ~/.ssh/github_key
# Tell SSH to use it for GitHub
$ echo "Host github.com" >> ~/.ssh/config
$ echo " IdentityFile ~/.ssh/github_key" >> ~/.ssh/config
# Copy public key to clipboard
$ cat ~/.ssh/github_key.pub | clip
Step 2 — Add to GitHub & Verify
# GitHub: Settings → SSH and GPG Keys
# Click "New SSH key" → paste → Save
# Test the connection
$ ssh -T git@github.com
Hi charaka-dev! You've successfully
authenticated, but GitHub does not
provide shell access.

Cloning a Repository
Download a full copy to your local machine.

git clone downloads the complete repository — all history, branches, and files. Local changes stay local until you push.

Clone via SSH URL (starts with git@github.com:) if you've set up SSH keys — no password prompts ever.

The 3-Stage Git Workflow
Understanding where your changes live at each step.
Working Directory
Where you edit files.
Changes are untracked.
git add .
Staging Area
Snapshot of what goes
into the next commit.
git commit -m
Local Repository
Permanent record.
All commits stored here.
git push
GitHub Remote
Online, backed up,
shareable with all.
Think of staging like packing a suitcase. Choose exactly which changes go into this trip (commit). Add, remove — until you zip it up (commit) and check it in (push).

Your

Write it like a pro from day one.
Conventional Commits Format
feat:New feature or enhancement
fix:Bug fix
docs:Documentation update
chore:Maintenance, config
style:Formatting, whitespace
Making Your First Commit
# Check what has changed
$ git status
On branch main
Untracked files: README.md, index.html
# Stage all changes
$ git add .
# Commit with a Conventional Commit message
$ git commit -m "feat: initial project setup with README"
[main (root-commit) a1b2c3d] feat: initial project setup
2 files changed, 10 insertions(+)
You just made history — literally.
Commit hash a1b2c3d is a permanent, immutable record in your project's timeline.

Part 4 — Core Workflow
Pushing to GitHub
Upload your local commits to the cloud.

git push sends your commits from your local machine to GitHub. Your work is now safe, backed up, and visible to collaborators.

Local Repository
Your commits live here first
git push origin main
GitHub Remote
Now visible online
Terminal
# First push — set upstream (-u flag)
$ git push -u origin main
Enumerating objects: 3, done.
Writing objects: 100% (3/3), 720 bytes, done.
To git@github.com:charaka-dev/my-first-repo.git
* [new branch] main → main
Branch 'main' set up to track 'origin/main'.
# Every push after that:
$ git push
The -u flag sets the default remote branch — only needed on the first push. After that, plain git push does it.

$ git status # see what changed

$ git commit -m "feat: ..." # save snapshot
$ git push # upload to GitHub
## SYNC FROM GITHUB
$ git pull # get latest from remote
## USEFUL EXTRAS
$ git log --oneline # see commit history
$ git diff # see unstaged changes
